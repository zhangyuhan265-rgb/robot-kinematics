## 二、已验证可用的完整链路

### 上电（顺序不能省）

```
set_current_mode(fd, 0)      ← 必须第一步！示教器动过之后不设模式，poweron 会一直返回 -1
clear_error(fd)
set_servo_state(fd, 0)       ← 先归零
set_servo_state(fd, 1)
set_servo_poweron(fd)
轮询 get_servo_state(fd,0)[1] 直到 == 3     ← 命令成功 ≠ 已上电
```

### 下电（顺序相反）

```
set_servo_poweroff(fd)
set_servo_state(fd, 0)
```
反过来 `set_servo_state(0)` 在状态 3 下返回 `-4 (NOT_ALLOWED)`。

### 运动

- `moveJ`：`coord=0`，目标单位**度**，7 元组（第 7 位恒 0）
- `moveL`：`coord=1`，目标 mm + 度
- 都要先 `queue_motion_set_status(fd, True)`
- **不要用 `queue_motion_clear_Data`**（会触发示教器报 `0x3B02`），改用 `set_status(False) → (True)`

### 速度换算

**末端速度 ≈ 0.36 × `cmd.velocity`（mm/s）**
实测：vel 300 → 111 mm/s，vel 500 → 182 mm/s。要 100 mm/s 就给 280。

## 三、踩过的坑（按重要性）

1. **上电前必须 `set_current_mode(fd, 0)`** —— 否则 `poweron` 稳定返回 -1，而控制器只在示教器提示「指令 0x2002 参数错误」，SDK 侧完全看不到。
2. **启动竞争**：第一条运动指令可能让伺服 `3 → 1`（就绪），驱动器无报警。**同会话内重新上电重试即可**（不要断开重连）。`09`/`14` 脚本已内置，最多 3 次。
3. **Python 绑定缺陷**：`get_current_mode` / `get_speed` / `get_robot_running_state` / `get_robot_switch` 把输出参数声明成值传递，Python 读不出值。能用的：`get_servo_state`（返回 `[返回码, 状态]` **列表**）、`get_current_position`、`get_digital_input/output`。
4. **`recv_message(fd, cb)` 传 Python 回调会死锁**，别用。
5. **会话释放**：一个脚本 disconnect 后立刻重连，控制器可能拒连（`Connection refused`）。脚本之间留 10–15 秒。
6. **不要在已满足的状态上重复下命令**（如已停止再发 `state(0)`），会返回 -4/-1 并往示教器记错误。
7. **`get_robot_joint_param(fd, id, param)` 的 id 从 1 起**，传 0 返回 -1。

## 六、压测数据（可信度很高）

| 测试 | 结果 |
|---|---|
| 六轴巡演 50 轮（速度 60） | **50 / 50**，残差平均 0.081° |
| 六轴巡演 100 轮（幅度加大） | **100 / 100**，残差平均 0.087°，最大0.145° |
| 加"启动重试"之前 8 轮 | 5 / 8 (62%) |

两次压测**都只有第 1 轮需要重试，第 2–100 轮零重试** → 证明启动竞争只发生在会话建立那一刻。

其他实测：`moveL` 直线 0.5 m 回位 0.05 mm、0.2 m 回位 0.01 mm；急停按下 `3 → 0` 约 0.2 秒。
