### SDK 能不能改控制器的 DH / 零位？（2026-11-07 实测结论：不能）

| 想改的东西 | SDK 接口 | 结论 |
|---|---|---|
| `L1..L6`（DH 长度） | 只有 `get_robot_dh_param`，**没有 set** | **改不了**，只能用示教器 |
| 关节零位偏移（off5） | 有 `set_zero_pos_deviation(fd, axis, shift)`，**但没有 getter** | **不能盲写**：写了读不回来，备份不了、回滚不了 |
| 把当前位置设为零点 | `set_axis_zero_position(fd, axis)` | 更危险，会一次性抹掉该轴零位 |

`RobotJointParam` 里也没有零位字段（只有 direction / 限速 / 软限位 / 减速比 / 编码器分辨率）。

→ **结论：DH 和零位都交给示教器操作的人做。** 脚本只负责：读参数备份、改完验证。

### ⚠️ 精度现状：折叠姿态下还有 ~25 mm 残差

2026-11-07 用两个位姿的实测法兰高度核对（d4 = 750）：

| 位姿 | 模型 | 实测 | 差 |
|---|---|---|---|
| A 参考位姿（q4=q5=0）| 1727 | 1735 | **−8** |
| B 600 测试终点（肘下折 52°）| 1041 | 1015 | **+26** |

## 五、⚠️ 现场测量方法：哪些可信，哪些别用

| 方法 | 可信度 | 说明 |
|---|---|---|
| **竖直卷尺**（地面 → 某个轴心） | ✅ **可信，±5 mm** | 本次全套结论都靠这个 |
| 高处物体的水平投影（无吊线） | ❌ **不可信** | 法兰在 1.75 m 高时，**3.6° 目测偏差 = 110 mm** |
| 地面标两点量位移 | ❌ **不可信** | 同上的问题。测过一次 1150，几何上限只有 1057 |
| 手机/照片比比例 | ⚠️ 只能粗筛 | 实测系统性偏高 11~22% |

**量水平位置一定要吊线**（线坠/激光），否则别量。

### 判"某个面水平"的坑

- 水平仪必须放在**要判定的那个面**上
- 法兰有**两面**：安装面（有螺栓孔）和背面。两面平行，但哪面朝上决定了法兰轴朝哪
- **螺栓孔是通孔，从哪面都能看见**，不能靠"看得见孔"判断正反
- 判法兰轴方向最直接的办法：**看螺栓从哪个方向拧进去**
- 本次踩过：把水平仪放在**腕部外壳顶面**上，测出来的不是法兰面

## 六、⚠️ 风险与禁令

1. **不要用控制器做笛卡尔运动**
   `moveL`、给 TCP 位姿、直线插补 —— 全部会偏。长度错到 44% 加上 J5 差 90°，实际轨迹可能完全偏离预期。
2. **可用的是关节空间**：`moveJ`、关节直线插补。这类指令不经过正运动学，参数错了看不出来
   （所以之前的压测、姿态巡演、50 轮往返全都"正常"，那些不能当精度证据）。
3. **不要用 controller 报的 TCP 做任何判断**
   `get_current_position(fd, 1)` 返回的位姿是它用自己的错参数算的。
   例：home 位姿它报水平距 1349 mm，真实约 1040 mm。
4. **绝对高度别直接取控制器 z**
   控制器基座原点是否在安装面上尚未确认（可能低 54 mm）。

## 八、标准参考位姿（现场核对用）

**2026-11-07 现场最终确认的两个参考位姿。** 五个轴在零位，没有任何零位偏置假设，
是判断"模型还准不准"最干净的基准。

### 位姿 A：`q = [0, 0, 0, 0, 90, 0]`（法兰面竖直）

| 量 | 模型 | 实测 |
|---|---|---|
| 大臂 | 竖直 | ✓ |
| 小臂管 | 水平 | ✓ |
| 肘 J3 离地 | **1557.5** | **1557** ✓ |
| J4/J5/J6 等高 | **1713.5** | 观察一致 ✓ |

| 水平半径（离 J1 轴）| **1052.5** | **~1070**（+1.7%）|
| 法兰面 | 竖直（法线水平）| ✓ |

### 位姿 B：`q = [0, 0, 0, 0, 0, 0]`（法兰面水平朝下）

| 量 | 模型 | 实测 |
|---|---|---|
| 法兰中心 离地 | **1581.0** | **1580** ✓ |

### 用法

怀疑模型时，摆到位姿 A，量三个数：

1. 肘离地 = **1557.5**
2. 法兰离地 = **1713.5**
3. 水平半径 = **1052.5**

三个都对 → 模型没问题；哪个不对 → 直接知道是哪一段的问题。

## 陷阱：PYTHONPATH 会覆盖掉环境里正确版本的 SDK

现象：`connect_robot` 返回正数、`get_connection_status` 返回 SUCCESS，但**每一条指令都返回 −1**，

## 水平方向验证完成（2026-11-07）

- **`a1 = 170` 已用钢板尺直接量确认**，模型不改。至此六个长度全部落实（其余 5 个靠 12 个位姿的高度，RMS 4.2 mm）。
- **水平尺度没有误差**：用恒姿态纯平移命令走 300 mm，实测 290 / 320 / 610，三点严格自洽（290+320=610），
  且没有任何单一尺度能同时解释两条弦 → 属标点噪声。详见 `仿真真机对齐度报告.md` 第七节。
- **铅垂法（吊线落地量弦长）已废弃**：法兰盘面朝下、看不见中心，绳的挂点每次不同，
  量到的是 `R+δ`，重复性 ±80 mm，分辨不了 50 mm 的差异。
- 两条操作教训：
  1. 铅垂要在**伸展位姿**下标点；折叠位姿下绳会被臂体挡住带偏（本次 P3 偏了 20 mm）。
  2. 要抵消挂点偏心，**两端姿态必须完全相同**（先解 IK 再 moveJ，或 moveL）；
     用折 q2 的方式「后移」会让法兰转动，δ 不抵消。
